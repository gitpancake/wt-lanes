The lane OWNS its review feedback loop end-to-end. Reviews (Devin, Greptile, Codex) fire automatically on push; the REQUIRED `arbiter` commit status synthesizes them and re-runs 3-5 min after each reviewer round, so the FIRST verdict on a sha is stale by construction. ONE call per round, inseparable from the push. {{include:gate-call}} It triggers Devin when needed, waits for a SETTLED verdict (arbiter status newer than every reviewer post on the head sha, stable across two polls), then prints summary JSON plus EVERY finding on that sha (arbiter verdict, review bodies, inline comments). Exit 0 = arbiter success → finish. Exit 5 = blocked, exit 6 = needs-human, exit 8 = needs-holland → fix EVERY 🔴/🟨/P1/P2 finding it printed (inline comments included), commit, push, gate again; a needs-human or needs-holland verdict withholds the merge, never the fix pass. Exit 4 = unsettled after ~9 min (the Bash tool kills anything past 10 min) → call gate once more; still 4 → `~/.claude/scripts/lane-pause.sh review 'PR #<N> review pending'` and stop, do NOT claim done. NEVER call `devin-review.sh status|trigger|wait`, never `sleep N &&` polls, never loop over `commits/<sha>/status` yourself — a hook denies all three. `devin-review.sh findings "<full PR url>"` re-prints the findings without waiting. The loop ends ONLY on exit 0 with zero unaddressed blocking findings, or on a hold after one full fix pass: exit 6 → `~/.claude/scripts/lane-pause.sh human 'PR #<N> needs-human: <what the maintainer must judge>'`; exit 8 → answer the arbiter's question for Holland as ONE PR comment starting with @holland-march-cartage (the decision, the evidence, the trade-off), then `lane-pause.sh holland 'PR #<N>: <the question> — answered at <comment url>'`; exit 9 → `lane-pause.sh prompt-owner 'PR #<N> awaiting <owner handles>'`. The cockpit watches a held PR and marks the lane done when the person releases it — never keep gating a hold. Chuck is RETIRED: never tag @chuck-noland-cartage, never poll for chuck-noland[bot] comments. A finding you judge wrong → one-line rebuttal in the final report, never a PR comment. Never post findings or replies to the PR yourself (`gh pr review --comment` or any other `gh` write); the Holland answer is the ONE comment a lane may post. Repo has no `.github/workflows/arbiter.yml` → skip the loop.
